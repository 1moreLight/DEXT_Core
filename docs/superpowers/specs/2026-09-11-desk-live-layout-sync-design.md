# DESK-LIVE-001 实时应用放置与 Widget 优先避让设计

## 背景

DESK-EDIT-001 已让配置器新增应用立即获得安全网格坐标，但真实桌面仍只会在“保存 → 应用 Room”后看到变化；新增位置也仍是从左上角逐行取得第一个空格。与此同时，配置器画布在 Widget 松手后会避让图标，真实桌面上的 Widget 拖动/缩放却不会移动冲突图标。

本工作包把“应用放入 Desk”和“真桌面布局编辑”收口成一条实时链：当前使用中的 Room 可立即收到图标成员变化；Widget 的布局优先级高于应用图标；用户可选择新增后是否自动最小化配置器并进入桌面编辑。

## 目标

1. 新图标优先加入现有图标组附近，而不是机械占据左上第一个空格。
2. 当前使用中的 Room 新增或移除图标后，无需再次手动保存、应用或重启壁纸即可更新真实桌面。
3. 默认在新增成功后关闭选择器、切到目标 Desk、最小化配置器，并让真实桌面进入编辑模式且高亮新图标。
4. 设置页允许关闭“放入应用后前往桌面编辑”；关闭后仍实时同步，但不最小化、不自动进入编辑。
5. 真桌面拖动或缩放 Widget 后，重叠图标自动移动到最近的合法网格，Widget 优先。
6. 桌面产生的图标坐标和 Widget placement 回到配置器时能够安全合并，不覆盖其他未保存草稿。

## 非目标

- 不恢复 Desk↔Dock 拖拽、桌面删除按钮或图标尺寸切换。
- 不改变 DockEditor 作为 Dock 图标唯一管理入口的定位。
- 不让非当前 Room 在后台替换正在运行的桌面。
- 不把全部配置器编辑行为改成实时协同编辑；本包只实时提交 Desk 图标成员/位置与真桌面 Widget 布局。
- 不引入云同步、跨设备同步、多显示器或多人冲突解决。
- 不删除 Room v2 的 `iconSize` 兼容字段和现有 `saveRoom` 桌面回写链。

## 方案选择

### 采用：针对 Desk 布局的完整快照热同步

配置器把目标 Desk 的图标数组作为一次受控布局更新交给 Rust。Rust 重新读取可信源 Room，只替换目标 Desk 的布局字段，完成 Schema/资源校验与原子写入；若该源 Room 正在运行，再同步运行包并通过 Core 向顶层官方宿主发送完整、可信的 Room 运行快照。宿主不重启 Player；目标就是当前 Desk 时只原地替换该 Desk 的图标数组并重绘图标层，让现有 Scene/Widget 实例继续挂载。只有自动前往另一个目标 Desk 时，才沿现有切桌路径正常卸载并挂载该 Desk 的 Scene/Widget。

这比自动调用现有 `apply_room` 更平滑，也比只发送 `addIcon/removeIcon` 增量指令更容易保证配置器、源 Room 和运行包一致。

### 放弃：自动执行保存 + 应用

可复用现有接口，但每次加入应用都会重新装载壁纸，造成闪烁、Scene/Widget 生命周期重启和输入焦点变化，不符合“加完马上拖”的目标。

### 放弃：仅发送增量图标指令

消息更小，但三端必须共同维护操作顺序、版本和重放，快速连续添加、撤销以及桌面回写都容易基于不同旧状态，收益不足以覆盖复杂度。

## 用户体验

### 放入应用

1. 用户在某个 Desk 的“放入应用”选择器点击未选应用。
2. 配置器立即计算新图标位置并更新界面。
3. 若 Room 正在运行，配置器提交目标 Desk 图标快照并等待热同步确认。
4. 默认偏好开启时，成功确认后关闭选择器，向真实桌面发送“切到目标 Desk、进入编辑、高亮此启动目标”，再最小化配置器。
5. 偏好关闭时，桌面仍收到新图标，但选择器和配置器保持不动，方便连续添加。
6. 点击已选应用表示移除；移除也实时同步，但不自动最小化或进入编辑。

设置页“偏好设置”新增：

- 名称：`放入应用后前往桌面编辑`
- 说明：`新增成功后最小化配置器，并在目标 Desk 高亮新图标`
- 默认值：开启
- 存储：配置器本地偏好 `dext.minimizeAfterDeskAppAdd.v1`，不进入 Core 通用设置或 Room 文件。

### 非当前 Room 与失败

- Room 未运行：只更新现有草稿/撤销历史，不最小化，提示“应用 Room 后可在桌面编辑”。
- Core 未连接：只保留草稿和选择器，不最小化，提示连接恢复后重试。
- 源 Room 已保存但运行包写入或消息发送失败：返回 `saved: true, liveUpdated: false`，更新配置器的已保存 baseline，但保留窗口并提示“已保存，桌面同步失败”；不得假装已经进入桌面编辑。
- 快速连续点击：同一 Room 的布局更新串行执行，并以最新待提交快照收尾，旧响应不得覆盖新状态。

## 智能图标放置

候选格必须同时满足：不与已有图标重合、不与任何 Widget 的安全矩形重合、不进入有效 Dock 保留区，并位于当前 `iconSize` 对应网格内。

桌面没有图标时，从左上安全区选择第一个合法格。已有图标时，对所有合法候选格按以下顺序确定性评分：

1. 优先与更多现有图标正交相邻，使图标组趋向紧凑并优先填补组内空洞。
2. 再选择到现有图标集合最小曼哈顿距离更短的格子，使新图标贴近现有图标组边缘。
3. 分数相同按从上到下、从左到右稳定排序，确保预览、测试与运行态结果一致。

新增只决定新图标的初始位置，不为了腾位置主动重排其他图标；满网格仍返回明确失败。

## Widget 优先避让

### 拖动过程

- Widget 本体持续跟随指针并按现有 1920×1080 逻辑画布钳制。
- 根据当前候选 placement 计算会冲突的图标及其候选落点，以半透明占位预览结果。
- 实际图标数组在 pointerup 前不变，避免拖动过程中反复跳动和持续写盘。
- 若没有完整合法解，Widget 边框显示冲突态；其他图标不移动。

### 松手提交

1. 最终 Widget 矩形及 40 逻辑像素安全边距优先占位。
2. 未冲突图标位置固定，只对冲突图标求解。
3. 每个冲突图标按离原格曼哈顿距离由近到远寻找空格；候选必须避开所有 Widget、Dock、未冲突图标和已经分配的新位置。
4. 多个图标按“可用近邻最少者优先”处理，再按原数组顺序稳定打破平局，降低先到图标抢占唯一近邻的概率。
5. 全部图标都有合法落点时，Widget placement 与图标坐标作为一个事务更新并调用一次 `persistRoom()`。
6. 任一图标无合法落点时，Widget 与全部图标恢复拖动前状态，并显示“空间不足，Widget 已恢复原位”。

移动和缩放使用相同规则。配置器画布在被 UI-008 删除前维持同样的评分、回退和提示语义。

## 数据与消息流

### 配置器 → Rust

新增受控命令接收：可信 Room 目录、Desk 索引、干净的图标数组，以及可选的运行时动作（目标 Desk、是否进入编辑、待高亮启动目标）。命令不得接受或相信客户端提供的 `__source`、运行包路径或任意写入目标。

Rust 的执行顺序：

1. 规范化并验证 Room 目录属于当前库的合法 Room。
2. 读取源 `room.json`，仅替换目标 Desk 的 `icons`。
3. 验证 Room v2 结构和素材引用。
4. 在布局同步锁内原子写回源 Room；源 Room 是本次操作的事实源。
5. 通过运行包现有可信 `__source` 判断它是否为当前 Room；只有匹配时才在同一串行边界内原子更新运行包 `room.json`，保留可信戳。若此步失败，不回滚已经可靠落盘的源 Room，而是明确返回“已保存但未热更新”。
6. 调用现有 `SendMessageWallpaper` RPC，把新的显式消息类型发送给运行中的官方宿主。
7. 返回 `saved`、`liveUpdated` 和规范化布局快照。

### Core / Player → 官方宿主

新增显式 Room 布局更新消息类型；Core 只向匹配的 Dext 官方运行包发送，Player 沿现有顶层官方页面通道注入。消息包含已验证的 Room 快照、目标 Desk、进入编辑标记和一次性高亮目标，不携带文件写入路径。

宿主收到后：

- 检查消息类型、Room v2、Desk 数量与目标索引；非法消息不改变当前状态。
- 保留运行态集合（如运行中应用圆点）；同 Desk 只把可信快照的目标 `icons` 合并进当前 `ROOM` 并重绘图标层，不替换现有 Widget 对象引用。
- 偏好关闭时不主动切 Desk；若目标恰好是当前 Desk，则立即重绘图标层，否则只更新内存中的目标 Desk 数据。
- 偏好开启且目标 Desk 不同时，才切到目标 Desk 并沿现有 `renderDesk` 路径重绘；需要时调用现有 `enterEdit()`。
- 新图标高亮仅是短时 DOM 状态，不写入 Room。

### 桌面 → 配置器

真桌面仍使用已验证的顶层 `saveRoom` 上行链原子双写源 Room 与运行包。配置器窗口重新获得焦点时读取源 Room，只合并以下 live-layout 字段：

- 图标成员及 `x/y` 坐标；
- Widget 的 `placement`。

背景、Scene、switch、Dock、权限声明及其他未保存草稿不被源文件覆盖。合并同时更新对应 baseline；只有其他字段仍与 baseline 不同才继续显示未保存。

## 撤销与一致性

- 应用选择器的加入/移除继续进入现有撤销历史。
- 对当前运行 Room 执行撤销/重做时，如果 Desk 图标成员或坐标发生变化，复用同一布局同步队列；其他字段仍保持普通草稿语义。
- 配置器最小化前必须等待热同步成功确认，防止桌面尚未更新就失去操作反馈。
- 所有基于旧 JSON 的读改写都必须在同一串行锁内，原子临时文件名继续按写入唯一，遵守 ERRORS #34。

## 安全边界

- 所有磁盘目标由 Rust 规范化 Room 和运行包可信 `__source` 推导，拒绝页面或配置器消息提供路径，遵守 ERRORS #30。
- Room 更新前先完整验证，验证失败不得清理或部分覆盖当前运行包，遵守 ERRORS #27。
- WebView 上行仍只接受顶层官方页面；新增下行消息不开放给 Scene/Widget iframe，遵守 ERRORS #31。
- 本包不恢复跨 Desk/Dock 指针捕获，不触碰 ERRORS #65 已取消方向。

## 测试与验收

### 自动检查

- 智能放置：空桌面、紧凑成组、组内空洞、Widget/Dock 障碍、满网格、三档历史网格、确定性和输入不可变。
- Widget 避让：单/多图标、移动、缩放、其他 Widget、Dock、边缘、候选争抢、无解整体回退、只移动冲突项。
- Rust：非法路径/Desk、非 v2、素材校验失败、非当前 Room、可信戳、源/运行包各自原子写入、部分失败结果以及并发串行。
- 消息转换：新增类型序列化/反序列化以及错误负载拒绝。
- React：偏好默认开启/持久化、成功后最小化、关闭偏好不最小化、非当前 Room/失败不最小化、快速更新最后写入获胜、焦点合并不覆盖其他草稿。
- 渲染器：热更新不重启页面、切目标 Desk、编辑态、高亮、运行圆点保留、Widget pointerup 单次持久化。
- 必跑 `npm test`、`npm run build`、`node --check`、Rust 测试、`scripts/build.ps1`、`scripts/start.ps1`、Room Schema 与 `git diff --check`。

### 人工验收

1. 默认偏好下向当前 Room 加应用，无需保存/应用，配置器最小化，桌面切到目标 Desk 并高亮新图标，可立即拖动。
2. 关闭偏好后连续添加，真实桌面持续更新但配置器和选择器不退出。
3. 编辑非当前 Room 或 Core 断线时不错误最小化，草稿和提示正确。
4. 新图标围绕现有图标组放置，不覆盖图标、Widget 或 Dock。
5. 真桌面移动和缩放 Widget，冲突图标仅在松手后移动到最近安全格；重启后布局保持。
6. 制造无可用格场景，Widget 与图标整体回退且没有重叠或丢失。
7. 返回配置器后能看到桌面布局变化，其他未保存属性仍保留。
8. Dock 管理、双击启动、运行状态圆点、Desk 切换与 Widget 内容不回归。
