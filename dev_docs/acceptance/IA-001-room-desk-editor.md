# IA-001 Room/Desk 编辑信息架构（WP1–WP6）

- 状态：待验收
- 分支：`cursor/room-desk-ia-36db`
- 目标：编辑只走 Room v3 统一编辑器；作品 / 我的 / 本机设置分层可见；Dock 固定项改为全局加本 Desk 追加。

## 范围外

自动启停应用、勿扰、多显示器、自定义转场编辑器、创意工坊、AI 生成升级、把 `dock-preferences.json` 与 `application-dock.json` 合并成一个文件。

`wallpapers/dext-room/` 与 v2 schema 仍留在仓库：图标几何测试和历史宿主还引用它们。配置器不再提供 v2 画布、流程或 Dock 编辑器，打开 v2 Room 只显示不支持说明。

## 行为

1. Room 库对 v2 / 未知版本显示「不支持」，不进入旧编辑器。
2. v3 只有一个编辑入口：房间库 → 统一编辑器。左侧 Room/Desk 树，右侧属性。顶部切换「作品 / 我的」。
3. 可编辑字段带来源：作品、我的覆盖、本机设置。本机设置只在设置页。
4. 「我的」写 `personal.json`，不改「作品」里的 room.json 值。「恢复为作品值」清除对应 L2 项。
5. 桌面长按写入的布局出现在「我的」布局列表，可逐项恢复。
6. Room 编辑器没有 Dock 显示方式、高度、自动隐藏。
7. 设置页只有显示方式里的一个自动隐藏选项。保存时同步应用 Dock 的 autoHide / reserve。状态文案同时写请求和实际。
8. 固定项是全局列表加上本 Desk 追加。空的 Desk 列表表示没有追加，生效结果等于全局。没有“独立空列表”模式。
9. Dock 呈现同时显示请求与实际。请求主题融合但实际不是主题时，显示回退原因。

## dockPins 迁移

旧 `personal.json` 的 `dockPins` 是整表覆盖。第一次读取时，若 `dockPinsAppend` 不为 true：

- 追加项 = 旧列表里目标不在当前全局固定项中的项
- 然后写入 `dockPinsAppend: true`
- 生效固定项 = 全局 ∪ 追加项

因此旧列表里曾经可见的 Desk 专有项会保留。旧覆盖故意藏掉的全局项会重新出现，因为追加模型不能表达“从全局移除”。空数组不再表示独立空 Dock，而表示没有追加。

## 人工验收（Windows）

本环境不能运行 WPF。请在 Windows 上：

1. 房间库点一个 v2 Room 的「不支持」，确认只有说明，没有画布 / 流程 / Dock 旧编辑器。
2. 打开一个 v3 Room，确认只有这一条编辑入口；切换「作品 / 我的」，字段旁有来源标签。
3. 在「我的」改按钮或布局后切回「作品」，作品坐标和默认动作不变。对一项点「恢复为作品值」，该项个人覆盖消失。
4. 桌面长按挪一个图标，回到编辑器「我的」，能看到同一坐标，并能恢复。
5. 确认 Room 编辑器没有自动隐藏、高度、显示方式。设置页只有一个自动隐藏入口（显示方式里的「触边展开」）。保存后，状态文案里的请求和实际一起变化。
6. 固定项切到当前 Desk：全局项标「跟随全局」，追加项标「本 Desk 追加」。清空追加后 Dock 仍显示全局项。
7. 把显示位置设为「融入当前主题 Dock」。主题不可用时，界面同时给出请求、实际和回退原因。
