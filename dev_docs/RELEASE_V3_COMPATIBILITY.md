# v3 首发与后续程序升级兼容
首发候选固定为Room格式3、作者API1、宿主协议1、安装快照1、个人数据1；公开词汇见根目录room-v3-compatibility.json。协议属于宿主，不要求作者清单新增私有协议字段。
发布前候选样包在fixtures/room-v3/release-api1：六套作者目录及六个分享zip，catalog.json保留UUID、资源长度与SHA256。当前只是源码准备，首次发布资格仍等真实Core/Player验收。
## 支持和更新
支持版本按完整既有契约严格读取，未知能力/动作/媒体/组件角色/转场不能解释成旧动作；提示更新程序并保留原件。缺少私人授权或绑定不等于格式不兼容，需由用户本机配置。
尚无已公开发布的另一v3契约，因此当前没有隐式转换。以后需要转换时新增独立版本适配和明确“生成升级副本”入口，保留原zip、作者目录和旧UUID对应的个人数据；新副本身份按正式复制规则处理。不允许为了通过读取而删除未知字段或直接覆盖原件。
## 每次Core/Player升级发布门槛
1. scripts/verify-release-rooms.ps1确认冻结作者字节/zip/契约未变，原始API1基线永久保留；新增版本另建基线与样包，不重写本目录。
2. 临时库导入六个原始zip→打开/试验台→应用→切Desk→默认/获准按钮→本机绑定/皮肤→普通重启→再分享；验证同副本私人覆盖、身份与资源保持。
3. 未知格式/API/能力清楚提示、支持作品仍可用，原件/私人覆盖未被升级失败清空；恢复支持版本可重试。
4. 填写独立验收卡V3-P10-002的实际版本/构建/样包摘要与结果。任何必选项缺证据或失败均不具备发布资格；暂不接自动推送。
只读摘要核对不代替实际能力、输入、媒体和系统恢复验收。最终恢复用户原状态；与v3发布收口共用一次集中冒烟，不扩大网络测试。
